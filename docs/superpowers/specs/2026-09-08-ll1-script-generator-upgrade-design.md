# LL(1) 脚本生成器升级设计

## 目标

升级现有 `.gram` 文法加载器、解析器生成器和动态变量运行时，使生成器能够从脚本文本直接完成词法分析与非递归 LL(1) 语法分析。升级后默认支持字符串、动态数值和变量标识符，支持通过 `%define` 声明固定字符串运算符，并支持在语义动作中显式定义或赋值变量。现有两个 Python 文件合并为单个 `parser_gen.py`，由同一个命令完成文法加载、分析报告和 C 代码生成。

本项目定位为面向教学和 MCU 的轻量 LL(1) 生成器，不实现 YACC 的正则词法规则、通用左递归处理或 LALR 分析。

## `.gram` 指令

### 默认 Token

生成器始终隐式声明以下 Token，无需在 `%token` 中重复声明：

- `STRING`：双引号字符串；
- `NUMBER`：带动态类型的数字；
- `VARIABLE`：C 风格变量标识符。

若 `%token` 中再次列出这些名字，加载器应去重而不是生成重复枚举项。用户声明的其他 Token 仍可通过 `Parser_Run()` 传入，但 `Parser_RunText()` 只能自动识别默认 Token 和具有 `%define` 规则的 Token。

### `%define` 固定字符串规则

`%define` 的格式如下：

```text
%define PLUS "+"
%define EQ "==|="
%define ASSIGN ":="
```

Token 名若尚未声明，由 `%define` 隐式加入 Token 列表。引号内只支持以 `|` 分隔的多个固定字符串，不支持正则表达式、字符类、重复、分组或其他 YACC/Lex 语法。转义后的 `\|` 表示字面量竖线，不作为分隔符。空分支、重复规则以及两个 Token 声明相同字面量均在加载阶段报错。

生成的 Lexer 使用最长匹配原则；长度相同时按 `%define` 的声明顺序匹配。因此 `==` 与 `=` 共存时优先识别 `==`。

## 默认 Lexer

### 字符串

`STRING` 使用双引号，支持 `\n`、`\r`、`\t`、`\0`、`\\`、`\"` 等常见 C 转义。Token 的语义值为 `VAR_TYPE_STRING`。未闭合字符串和不支持的转义应报告行号与列号。

### 数字

数字的符号不属于数字字面量，由文法中的正号或负号运算符处理，避免 `1-2` 中的减号产生歧义。默认类型规则如下：

| 形式 | 示例 | 动态类型 |
| --- | --- | --- |
| 十进制整数 | `1` | `int32_t` |
| 无符号整数 | `1u`、`1U` | `uint32_t` |
| 小数或科学计数法 | `1.2`、`.5`、`1e3` | `float` |
| 带 `d` 后缀的浮点数 | `1.2d`、`1e3D` | `double` |

`u` 仅允许用于整数，`d` 仅允许用于带小数点或科学计数法的数值。非法后缀、格式错误以及超出目标类型范围的字面量均为词法错误。

### 变量

`VARIABLE` 接受 `[A-Za-z_][A-Za-z0-9_]*`。Token 保存变量名称及其长度，不在 Lexer 阶段查找变量，以便同一个 Token 同时用于定义、赋值和读取。

### 空白与位置

Lexer 跳过空格、制表符和换行，并持续维护从 1 开始的行号与列号。所有词法错误、语法错误和语义动作错误均尽可能携带对应位置。

## 非递归 LL(1) 分析器

### 生成阶段

Python 生成器先把现有的直接左递归规则改写为等价的非左递归产生式，再计算最终文法的 `FIRST`、`FOLLOW` 和 SELECT 集合，最后生成预测分析表。

生成器继续接受现有的直接左递归写法。间接左递归、只有递归分支而没有基础分支、同一预测表单元出现多个产生式等情况均在生成阶段报错。

### C 运行阶段

生成的 C 解析器不再为每个非终结符生成递归函数，而是使用循环驱动以下固定容量结构：

- 分析符号栈；
- 语义值栈；
- 语义动作标记；
- 预测分析表。

展开产生式时，以逆序把右部符号和动作标记压入分析栈。右部全部完成后执行动作标记，使 `$$`、`$1`、`$2` 等仍对应源文法产生式的语义位置。栈容量通过生成代码中的配置宏设置；溢出时返回明确错误，不使用动态递归调用。

保留现有接口：

```c
VarValue_T *Parser_Run(const ParserToken_T *pTokens, uint32_t count);
```

新增文本入口：

```c
VarValue_T *Parser_RunText(const char *pText);
```

`Parser_RunText()` 使用生成的 Lexer 逐个产生 Token，并复用同一个表驱动解析核心，避免维护两套语法分析逻辑。

## 变量定义与赋值

### 语义动作

支持以下动作形式：

```text
def[$1] = $3;
def[$1, int32] = $3;
def[$1, int32[8]] = $3;
def[$1, $2] = $3;
[$1] = $3;
$$ = [$1];
```

语义如下：

- `def[$1] = $3`：用 `$1` 的变量名定义变量，以 `$3` 的类型定型并复制其值；
- `def[$1, int32] = $3`：按显式简单类型定义变量，并把 `$3` 转换为该类型；
- `def[$1, int32[8]] = $3`：按显式元素类型和固定维度定义数组；
- `def[$1, $2] = $3`：复制 `$2` 的简单类型或完整数组类型约束，再转换并复制 `$3`；
- `[$1] = $3`：查找已有变量，把 `$3` 转换为该变量的固定类型后写入；
- `$$ = [$1]`：读取变量并把变量值作为产生式结果。

变量定义后类型不可变。重复定义和给未定义变量赋值均为错误。`def` 的类型参数只支持简单类型和数组；若 `$2` 为字典、结构体或无有效类型的值，则返回类型错误。数组类型复制只复制元素类型、维度和长度约束，不共享数组存储。

变量注册表新增明确的定义与赋值接口，语义动作翻译器不得直接修改注册表内部结构。所有新函数遵循项目命名规范，并在 C 文件中添加中文文档注释和代码段注释。

## 固定类型转换

简单数值类型之间允许转换。浮点转整数时截断小数；转换结果超出目标类型范围时返回 `VAR_RUNTIME_ERR_RANGE`，且目标变量保持原值。字符串不自动转换为数字，数字也不自动转换为字符串。数组赋值逐元素转换，任一元素失败则整次赋值失败，目标数组保持原值。

定义和赋值应先构造或转换临时值，确认全部成功后再替换目标内容，以避免部分更新。

## C 语言 Getter

保留 `Var_ToInt()` 和 `Var_ToDouble()` 兼容已有代码，新增返回状态码和输出参数的强类型 Getter。至少覆盖运行时已有的所有简单类型：

```c
int32_t Var_GetInt8(const VarValue_T *pValue, int8_t *pResult);
int32_t Var_GetUint8(const VarValue_T *pValue, uint8_t *pResult);
int32_t Var_GetInt16(const VarValue_T *pValue, int16_t *pResult);
int32_t Var_GetUint16(const VarValue_T *pValue, uint16_t *pResult);
int32_t Var_GetInt32(const VarValue_T *pValue, int32_t *pResult);
int32_t Var_GetUint32(const VarValue_T *pValue, uint32_t *pResult);
int32_t Var_GetInt64(const VarValue_T *pValue, int64_t *pResult);
int32_t Var_GetUint64(const VarValue_T *pValue, uint64_t *pResult);
int32_t Var_GetFloat(const VarValue_T *pValue, float *pResult);
int32_t Var_GetDouble(const VarValue_T *pValue, double *pResult);
int32_t Var_GetChar(const VarValue_T *pValue, char *pResult);
int32_t Var_GetString(const VarValue_T *pValue, const char **ppResult);
```

Getter 不改变源变量。数值 Getter 使用与赋值相同的严格范围检查；转换失败时不写输出参数。`Var_GetString()` 只接受字符串并返回运行时持有的只读指针，其生命周期不超过源变量。所有指针参数必须显式与 `NULL` 比较。

## 文法分析报告

生成器每次运行默认向控制台输出简洁的文法分析报告，并支持：

```text
--report <输出路径>
```

将相同内容保存为 UTF-8 文本。报告包含：

1. 消除直接左递归后实际用于生成预测表的最终产生式；
2. 每个非终结符的 `FIRST` 集合；
3. 每个非终结符的 `FOLLOW` 集合；
4. 非终结符与向前看 Token 对应的预测分析表项。

产生式和集合按文法声明顺序稳定输出，集合中的 Token 按 Token 声明顺序排列。空串显示为 `%empty`，输入结束符显示为 `END`。发生 LL(1) 冲突时，错误信息同时列出冲突表项和相关产生式。

## 错误处理

新增或细化以下错误类别：

- `.gram` 指令和 `%define` 规则错误；
- 数字或字符串词法错误；
- 未知输入字符；
- LL(1) 冲突及左递归错误；
- 分析栈或语义栈溢出；
- 重复定义和未定义变量赋值；
- 不支持的类型推导；
- 数值范围错误；
- 数组长度或元素转换错误。

Python 生成阶段抛出带上下文的异常；生成的 C 运行时通过状态码和包含行列号的错误结构报告失败。为兼容现有 `Parser_Run()` 返回值，可增加 `Parser_GetLastError()` 查询最近一次错误，不破坏旧函数签名。

## 测试策略

### Python 单元测试

覆盖 `.gram` 加载、默认 Token 注入、`%define` 分支与转义、重复字面量检测、最长匹配顺序、直接左递归消除、最终产生式、`FIRST`、`FOLLOW`、预测表和语义动作翻译。

### C 运行时测试

覆盖所有 Getter、合法数值转换、浮点截断、上下界、越界后输出参数不变、字符串拒绝数值转换、固定类型赋值和数组事务性转换。

### 生成代码集成测试

测试流程为“加载 `.gram` → 生成 C → GCC 编译 → 执行脚本文本”。覆盖：

- `STRING`、`NUMBER`、`VARIABLE` 三个默认 Token；
- `int32_t`、`uint32_t`、`float`、`double` 数字推导；
- `%define EQ "==|="` 的最长匹配；
- 四种 `def` 形式、变量读取和固定类型赋值；
- 重复定义、未定义赋值、范围溢出和非法类型推导；
- 简单类型数组及多维数组；
- 深层输入不使用 C 递归栈；
- 直接左递归源文法兼容；
- Lexer、Parser 和语义错误的行列号；
- 控制台报告与 `--report` 文件内容一致且顺序稳定。

正式测试源码作为回归测试保留。测试生成的临时 C 文件、报告文件、日志和可执行文件必须在测试结束后清理，不留在工作区。

## 兼容性与范围限制

- 不再支持 JSON 文法输入，所有文法统一使用 `.gram` 文本；保留 `Parser_Run()`，现有用户可继续传入 Token 数组；
- `grammar_loader.py` 的实现合并进 `parser_gen.py`；仓库只保留一个正式 Python 生成器文件和命令入口；
- `.gram` 中原有 `%token`、`%start`、`%var` 和直接左递归写法继续有效；
- 原有 `VAR`、`IDENT` 不自动改名，但新文法推荐统一使用默认 `VARIABLE`；
- 不支持 `%define` 正则表达式；
- 检测并拒绝间接左递归，不自动改写；
- 不生成 YACC/LALR 状态机；
- `def` 类型推导只支持简单类型和数组，不扩展到字典或结构体。
